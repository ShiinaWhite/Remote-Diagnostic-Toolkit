## Implemented and verified

- Production Job Object resides in Rdt.Core and has only KILL_ON_JOB_CLOSE.
  Creation/configuration/assignment/membership failures prevent protocol startup.
- Both fixed image and exact upstream builtin hashes are checked before use.
  The verified image stays open without write/delete sharing through execution.
- Production starts agent-server --stdio; task content is sent over NDJSON only.
  Stdio is UTF-8 without BOM, with strict stdout/stderr decoding and no automatic
  decoder switch on BOM. The UTF-8 PowerShell contract prefixes operator tasks.
- Explicit YOLO, fixed local builtin/personal provider paths, private environment,
  and schema-checked runtime-preferences reverse requests. Unknown host requests
  are rejected; their redacted method name may be displayed, never their payload.
- Existing scrypt/AES-256-GCM vault and local credential-init are used. The real
  operator entered Key and PIN in a local hidden-input terminal. No secret was
  provided through chat, source, argv, environment or .env.
- Default nonsecret profile: domestic BigModel Coding Plan,
  `https://open.bigmodel.cn/api/coding/paas/v4`, `glm-5.3-flash`, Bearer auth through
  the OpenAI Chat Completions schema. Reasoning parameters remain at defaults.
- Production multi-line CLI: `rdt run operator.rdt`, terminated by a `.run` line.
  The historical READ ONLY mock remains a separate explicit entry.
- Original upstream Apache-2.0 license, NOTICE and third-party notices are copied
  byte-for-byte. RDT LICENSE remains UNDECIDED. No SEA binary is tracked in Git.

## Real Profile snapshot and attribution

The automated real-run evidence is retained as **PARTIAL**, because the whole
real `.zcode` directory's content hashes differed. Its result has not been changed
to PASS and no log directory was silently excluded from that comparison.

Read-only follow-up found concurrent desktop logging:

- The real CLI log contains four `zcode_protocol.process.memory_sample` entries
  in the run's observation window, with two already written before RDT's runtime
  started. Subsequent pairs occur 60 seconds later with the same session/event
  counters. They are periodic observations of pre-existing processes.
- The real desktop log continued being written after RDT's audited exit and
  complete Job/Session cleanup. Desktop ZCode processes had been independently
  observed running during the real test.
- The RDT session identity was absent from the inspected real CLI log. RDT's
  launch contract and pinned runtime direct profile and log paths into the private
  Session; its temporary files were inspected before deletion.

These facts explain why an idle desktop application can still invalidate an
unattributed whole-directory equality check. They support RDT's configured
isolation, but do not turn the original global hash comparison into proof that
every byte of the real Profile remained unchanged. Exact global Profile equality
is therefore **CONFOUNDED BY CONCURRENT DESKTOP LOGGING**, not a PASS claim.
The operator requested avoiding further quota consumption; no paid test was
repeated. External Review should assess this observation separately from the
successful real G execution and production lifecycle checks.
